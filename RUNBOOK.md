### TRAPS
**The time scrubber cannot reach the event data.** It spans only the CURRENT week (from this week's Sunday), and events start tomorrow onward, so scrubbing can never show a fixture. Cost real time on 2026-08-28: I "verified" arena heat by scrubbing and watching Navy Yard climb, and was actually watching its ordinary evening curve. Fake the clock instead (`addInitScript` overriding `Date`), which is how three real bugs then surfaced at once.

**A guard can stop being OBSERVABLE without breaking.** Adding the Ticketmaster key silently disabled the only test of the low-water alarm: with a live source the fetch always returns a fresh 60 days, so the calendar can never be seen to run out, and every `--today` came back exit 0. Hence `--no-fetch`. Distinct from the usual "guard never fired" trap and harder to notice.

**GitHub Actions run in UTC; hum is about one city.** A manual run at 03:32 UTC decided it was already the 29th and pruned four shows still happening in DC at 23:32. The scheduled 12:40 UTC run is the same calendar day either way, so this would never have shown up on the cron. Dates now come from `America/New_York`.

**`venues: [...]` is not always a list of venues.** Four spots use it as INFO CHIPS and one as vibe copy: `clocktower` is "Free entry / Wed-Sat 9am-noon", `peopleshouse` "Free timed passes / Resolute Desk replica", `natgeo` "Immersive theater / Timed entry", `dcimprov` "18+ shows / Headliner weekends", `bliss` "18+ nights / Afrobeats Saturdays / HBCU crowd". Appending a real venue to those renders as "Free timed passes - Resolute Desk replica - The Army and Navy Club". Check what a spot's array actually contains before adding to it. (2026-08-28: caught on inspection after appending five private clubs to exactly these.)

**`spot.busy` is a RELATIVE heat weight, not a capacity.** 15-92, median 45, hand-authored. It belongs in `liveBusy()` (how much should this glow against other spots) and nowhere near a percentage. Feeding `liveBusy` into `crowdWord` meant **107 of 116 spots could never display "Packed"** even at 100% live busyness, and a spot weighted 30 needed a live reading of 116% to reach "Steady". `busyLevel()` is the one to band on — fullness relative to the place's own peak, unscaled. Estimated spots are capped at 75 there so an estimate can never claim "Packed" or "Surge".

**A heatmap SUMS its points, so paint values are tuned to a point count.** 116 spots looks right; the same settings with 382 bars merge northwest DC into one unreadable blob. `heatDensityScale()` compensates linearly against `SPOTS.length`. Verified by sweeping x1.0/0.5/0.3/0.2/0.12 against a real 382-venue render — usable range was 0.2-0.3.

**Placing a venue: category beats distance.** Phantom and Cafe Citron are nearest to Surfside, a taco stand; Shenanigan's is nearest to Tryst, a cafe. Rank by distance, then prefer a spot whose category matches the kind of place.

**Nobody types the apostrophe.** Search `fold()` normalised diacritics but not `'`, so "madams organ" found nothing — the flagship venue was unfindable by name, along with Dan's Cafe, Perry's, Duke's Grocery and Little Miss Whiskey's. Fixed 2026-08-28; watch for the same in any new matcher.

**OpenStreetMap is the free way to locate a venue.** Overpass by name inside the DC bbox found 21 of 29 missing venues with coordinates and street addresses, free and keyless. The 8 misses (Soundcheck, Saint Yves, L8, Club Elevate, Cloak & Dagger, Dirty Bar, Culture, and SoHo House) simply are not mapped — absence from OSM is not evidence a place does not exist.

**The app uses HASH routing — `#/u/<handle>`, `#/spot/<slug>` — and the slug is `slugify(name)`, not the spot id.** `router.js` says why in a comment: Pages 404s on real path routes. Cost time twice on 2026-08-28: `?spot=admo` silently does nothing, and testing `aviwise.github.io/hum/u/aviwise2` returns a Pages 404 that looks like a broken deploy. It is not — `#/u/aviwise2` is 200. A filed bug report was withdrawn over this.

**A cached reading with no age bound is a fossil the interface calls live.** `busy-live` fell back to `return json(cached ?? …)`, so once BestTime's quota ran out it served whatever was in `live_cache` for ever — Adams Morgan's sheet showed "live: 35% full - Quiet right now" from a reading taken **63 hours** earlier. Fixed 08-28: cache older than 90 min is refused and the function returns `{live_available:false}`, which the client already handles by falling back to the forecast. Same shape as F2: a label asserting something the system does not do.

**`NOT IN` against a column you just made nullable silently switches the predicate off.** Making `dm_reports.thread_id` nullable (so a moderation case survives the account deletion that destroys the thread) broke `purge_expired`: `thread_id not in (select thread_id from dm_reports where reviewed_at is null)` is NULL — never true — for every row once one NULL is in that set. DM retention stopped entirely, with no error, still reporting "0 rows", which is also what it reports when there is nothing to do. `retention-test` caught it. Add `and <col> is not null` to every `NOT IN` subquery, and check the existing ones whenever a column becomes nullable.

**`ON DELETE SET NULL` is an UPDATE, so BEFORE UPDATE guards fight it.** `delete_my_account()` failed with a foreign-key error pointing at `delete from auth.users` — which reads like a broken cascade and is not. `room_update_guard` and `dm_reports_update_guard` freeze columns whenever `auth.uid()` is not null, and the RI action runs inside the deleting user's own session, so the guard put the value back. The same guards were also silently reverting the deletion's own detach of reported content. Fix is a transaction-local flag (`hum.account_deletion`) that only the deletion path raises. Before adding another SET NULL, enumerate the BEFORE UPDATE guards on that table — there were exactly two in the schema, and both mattered.

**Revoking one column means revoking the whole table grant first.** A table-level `GRANT SELECT` covers every column and a single column cannot be revoked out of it — `revoke select on t from anon` then `grant select (…every column but the one…)`. And PostgREST refuses the *entire* request for any client that merely names an unreadable column, so the client has to ship before the revoke: F6 went out as two migrations (`zc` stops writing, `ze` revokes reads) with the deploy in between, or the live site would have 403'd its own profile reads.

**Inserting into `auth.users` directly gives every later sign-in a 500.** GoTrue scans `confirmation_token`, `recovery_token`, `email_change_token_new`, `email_change`, `email_change_token_current`, `phone_change`, `phone_change_token`, `reauthentication_token` into non-nullable Go strings, so NULLs there produce `Database error querying schema` — which looks like a broken database and is a broken fixture. Set them all to `''`. Test fixtures build users this way on purpose, to stay off the signup throttle.

**`posts` has a `sane_expiry` check: `expires_at > created_at AND expires_at < created_at + 13 hours`.** A backdated fixture "expired a day after it was made" is refused.

**Do not glob-delete inside `.impeccable/` — it is gitignored, so there is nothing to restore from.** On 2026-08-28 `rm .impeccable/probe-*.mjs` destroyed nine pre-existing probe scripts while cleaning up four scratch ones. Only `probe-prod.mjs` was recoverable, because its contents happened to be in that session's scrollback. `probe-acct-prod`, `probe-box`, `probe-dive2`, `probe-google-prod`, `probe-poi`, `probe-pulse`, `probe-rank` and `probe-tabs-prod` are gone. There are no Time Machine snapshots on this Mac.

**Verify what RENDERS, not what the markup says.** After the hum. rename I checked the title tag, the OG tags and the manifest, declared it done, and Avi said it still showed "out." He was right. The header wordmark is split across elements — `>out<span className="wordmark-dot">.</span>` — because the period is styled plum, so the string `out.` never existed contiguously in the source and four text searches could not see it. One screenshot at mobile width found it instantly. For anything a person LOOKS at, screenshot it.

**Cloudflare proxy in front of GitHub Pages with SSL mode "Flexible" is a redirect loop.** Not hit yet — it is waiting for the `hum.concordiastudios.com` move. Use a **DNS-only (grey cloud) CNAME → aviwise.github.io** and let GitHub issue the cert; if the orange cloud is ever switched on, SSL mode must be "Full".

**Supabase throttles signups — do NOT run all eleven suites back to back.** Doing so returns `over_request_rate_limit` partway through, and the suites then fail with `TypeError: Cannot read properties of null (reading 'id')` at `mk()`, which looks exactly like a code regression and is not. Worse, `mk()` sits OUTSIDE the try/finally in most suites, so a crash there strands test accounts that the next run cannot recreate while the limit holds. Cost ~10 minutes of diagnosing two "failures" on 2026-08-28. Run them in batches, or wait out the window (~15 min) and re-run.

**"Both doors" is a phrase to distrust.** Twice now I have written that something is guarded at both doors and been wrong about the count — reserved names turned out to have four (orgs, groups, signup, rename), and .edu verification had two paths where I had tested only the one a legitimate user takes. Enumerate the doors before claiming they are all shut.

**TestFlight is not needed to put the app on your OWN phone.** Cost real time on 2026-08-28 by treating an expired TestFlight profile as the blocker for a device install. Xcode + a paid developer account installs directly; see the recipe in NEXT.

**A brand rename is not a sed.** Renaming out. → hum. had three landmines a global replace would have silently detonated: `out.set(...)` is a real variable in `push-send`, two spot descriptions end an ordinary sentence with "out.", and `src/data/spots.js` is full of prose. It was done as a script with a per-file whitelist and an assertion on every replacement (207 of them), which is the only way to know a rename touched what it claimed to. Old URL is dead: anything referencing `aviwise.github.io/out-dc/` needs `/hum/`.

**An edit script that asserts PART-WAY THROUGH throws away the edits it already made.** These scripts read once, mutate a string, write at the end — so an assertion failure on edit 4 of 5 discards edits 1-3 too, and the shell prints a traceback that reads like "nothing happened" rather than "three of your changes are gone." On 2026-08-29 that silently dropped `priceOf`/`statusOf` from TonightPage while appearing to have added them; the page then died with `priceOf is not defined` at a spot far from the real cause. Either assert every match FIRST and mutate after, or make each edit its own script.

**A string replace that silently matches nothing reports success.** Twice on 2026-08-27 an edit script ran clean and changed nothing — the pattern carried indentation the real line didn't have. Same failure shape as the guard that never fired and the policy that never matched: the absence of an error is not evidence of an effect. Every scripted edit asserts the match now.

**An empty state exercises almost no rendering.** `CommunityPage` crashed white for exactly the users who had content — a missing `bySpot` lookup — and the test passed because it only ever loaded the empty version. Seed the content path, and listen for `pageerror`.

**Playwright `isVisible()` is true at `opacity: 0`.** Also: `.map-zaway .map-home` never matched because the button is a SIBLING of `.map-gl`, not a descendant — a state class on the wrong ancestor makes a selector that always fails, quietly. Assert on computed opacity, and check the DOM relationship before writing the combinator.

**Piping a test through `tail` reports `tail`'s exit code.** A crashing suite looked green. `set -o pipefail`, or don't pipe.

**Check what the library already does before building a control.** I built a zoom slider for MapLibre's `tapDragZoom`, which already shipped double-tap-hold-drag. Avi's verdict: "buggy, ugly, and not at all like how Snapchat does it." Reverted whole.

**Capacitor gotchas (2026-08-27):** `env(safe-area-inset-top)` returns 0 in the WKWebView — use `StatusBar.setOverlaysWebView({overlay:false})` instead; Capacitor 8 uses SPM, not CocoaPods; and comparing build hashes across web (`base: /out-dc/`) and native (`base: /`) proves nothing, they are supposed to differ.

**Postgres triggers fire in NAME order.** Cost an hour twice on 2026-08-27: `posts_guard` sorts after `posts_audience_guard`, so the org byline was overwritten by the member's personal handle; and the suspension check sorted after `dm_guard`, so a suspended user got "wait until they answer" — right refusal, wrong reason. Name new triggers deliberately (`posts_org_guard`, `dm_aa_suspension`).

**An RLS policy that queries its own table is a runtime error, and the error looks exactly like a policy that correctly returned nothing.** The `org_members` roster policy recursed; two outsider tests were "passing" on the error. Use a SECURITY DEFINER helper. Corollary: always assert outsiders are FILTERED (`!error && length === 0`), never just `length === 0`.

**Postgres applies SELECT policies to the returned row of an UPDATE.** Burying a room message set `removed_at`, which made the row fail the read policy, and the error read `new row violates row-level security policy` — an error about the read phrased as an error about the write.

**SECURITY DEFINER changes `current_user` to the function OWNER.** A guard gated on `current_user in ('authenticated','anon')` was dead code for every real request — anyone could have set `kind='org'` on themselves. Gate on `auth.uid() is not null` instead.

**Pointer capture on pointerdown redirects the click**, killing tap-to-cycle; but deferring capture breaks dragging on a small handle, because the pointer leaves it on the first move and element-bound handlers stop firing. Answer: bind pointermove/up to the WINDOW for the duration of the drag. Also swallow the one click after a real drag — a shrinking sheet releases ON its own handle.

**Chrome disables the Push API in incognito, and every Playwright context is incognito.** Use `launchPersistentContext` or `subscribe()` throws "Registration failed - permission denied" with no hint why.

**headless Chrome HAS `navigator.share`, and its share sheet silently does nothing** — indistinguishable from a broken button. Delete `Navigator.prototype.share` to force the copy branch, and read the REAL clipboard rather than stubbing it.

**Test-order self-sabotage**: a "probe" that does a real send/write burns the daily cap or ledger key, after which the real test passes while testing nothing. Probe with dryRun.

Headless Chrome `--window-size` at phone widths renders a ~528px CSS viewport on this Mac — screenshots lie; use playwright-core with `channel: 'chrome'` (script kept at `.impeccable/capture.mjs`).
Bundlers drop maplibre-gl's worker (rolldown-vite build emits nothing; dev optimizer 404s it) → map hangs forever, ZERO console errors. Fix in place: worker + shared chunk ship from `public/` with `setWorkerUrl('/maplibre-gl-worker.mjs')`, postinstall re-copies them — keep versions lockstep when upgrading maplibre. Verify deploys by RENDERING the prod URL (`.impeccable/probe-prod.mjs`), never by curl 200.
MapLibre v6 writes INLINE `opacity` on marker root elements — any CSS opacity on `.gmark` itself silently loses (broke category fading for days unnoticed); style marker CHILDREN (.gmark-dot etc) instead.
Never set `position` on `.gmark` markers — styles.css loads after maplibre's CSS, so it silently overrides `.maplibregl-marker{position:absolute}` and every marker drifts right by its siblings' widths (cost an hour).
Hidden tabs freeze requestAnimationFrame → MapLibre renders nothing and `load` never fires; a blank map in a background-tab screenshot is not a bug.
Supabase functions that pin `set search_path = public` break pgcrypto — digest() lives in the `extensions` schema; always pin `public, extensions` (broke every insert until fixed).
Postgres regex: unescaped dots in the link filter meant '.com' matched "welcome"/"coming" — benign posts refused as links. Escape dots, use \m/\M word boundaries, and test both directions.
GitHub Pages CDN serves the OLD bundle for ~1-3 min after deploy — probe-prod can pass on stale JS (title unchanged). Wait until the prod HTML references the new hashed index-*.js before verifying behavior. **And that curl check is necessary but NOT sufficient.** On 2026-08-29 curl confirmed the CDN was serving `index-C8hN6rtC.js` while the verifying browser tab was still running `index-Ct7BqIP2.js` from its OWN http cache — every measurement came back at the pre-fix numbers and looked exactly like a deploy that had silently failed. There was no service worker involved. A plain navigation (even with ignoreCache) can reuse the cached HTML; only `reload` + ignoreCache actually refetched it. Verify the page reports the hash you expect BEFORE trusting any number it gives you.

Note the map needed NO bounds change for this — 55 of the spots were already outside the mobile opening frame and panning is not clamped, so "adding suburbs shrinks DC on screen" was wrong.

**THE FLOATING LAYER IS FROSTED GLASS NOW (2026-08-29), AND THE MAP HAVING TEXT IN IT IS THE WHOLE STORY.** Asked whether frosted would work, I measured twice and both measurements said yes while looking at the wrong thing: dropping opacity to 68% barely moved text contrast (15.65:1 -> 15.37:1 against a 4.5 threshold) and IMPROVED how the pill separates from a pale map (1.012 -> 1.108). The screenshot showed the actual failure — at 68% the basemap label ADAMS MORGAN reads straight through the pill, "AD" and "GAN" flanking it and letterforms behind the word Metro. **A contrast ratio cannot see text-behind-text; the interference is structural, not luminance.** That is what makes a surface over THIS map different from glass over a photo. The fix follows from what frosted glass physically is — not more transparent, more diffusing. Opacity held roughly steady and the blur widened: small chips 82% / blur 40px, nav pill 84% / blur 48px (largest surface, so it reads thickest). **The wider blur is free** — measured at 4x throttle during a continuous pan, the case where the backdrop re-blurs every frame, 40px pans no slower than 14px (median 33.3ms vs 33.9ms). The cost is the map redrawing, not the blur radius. Note the original 88% carried a comment about surviving "the pale northwest quadrant" — that instinct was right, so the frost was bought with diffusion rather than by overriding it.

**A THIRD PANE OF TRANSLUCENCY IS THE ONE THING THIS MATERIAL WILL NOT DO.** The tab capsule sits inside the nav pill, which is blurred, inside the tab bar, which is another. Stacking a light translucent surface on another collapses legibility, so `.tab-cap` reads as light caught ON the glass — top-lit wash, bright upper edge, soft floor — rather than more glass. Same rule applies to anything added inside the pill later.

**BUILD TRAP: WRITE `-webkit-backdrop-filter` BEFORE `backdrop-filter`, OR THE STANDARD PROPERTY IS DROPPED.** Where a rule declared the unprefixed property first and its -webkit- twin second, the minifier merged the pair and kept **only the prefixed one** — so the standard property was absent from the shipped CSS for every glass surface, including ones that predated the glass work (12 prefixed / 6 unprefixed). Reordering so the prefixed declaration comes first keeps both (12 / 12). `build.cssTarget` does NOT affect this — it was tried and reverted rather than left in as dead config. Check the built CSS, not the source, after touching any prefixed property.

**WEBKIT DOES NOT IMPLEMENT `prefers-reduced-transparency` — SO ON iPHONE IT IS AN IN-APP TOGGLE, NOT A MEDIA QUERY (2026-08-29).** Checked on the simulator, Safari 26.5 / iOS 18.7: **neither `reduce` NOR `no-preference` matches**, and per spec a supporting engine must match exactly one — both false means the query is UNKNOWN, not merely off. It stayed unknown with `ReduceTransparencyEnabled` written at the OS level. **That two-state check is the reusable way to ask whether an engine knows a media query at all**, as opposed to knowing it and being switched off. iPhone is hum's main platform for both the PWA and the Capacitor shell, so the CSS guard shipped earlier that evening was inert exactly where it mattered. Chrome does support it (confirmed by driving `Emulation.setEmulatedMedia` over CDP — Playwright has no `reducedTransparency` context option, but the protocol does).

The fix is `src/lib/prefs.js` + a switch in the account sheet, **outside the signed-in branch** because an accessibility preference should not require an account. It sets an `.rt-reduce` class from an explicit choice, falling back to the OS on engines that expose it, and **the media query no longer drives the CSS directly** — keeping both would make an explicit OFF impossible to honour where the OS says on. Applied in main.jsx before render so the glass never flashes in. `prefers-contrast: more` is separate and does work.

**Watch specificity when adding a global override class.** `.rt-reduce .pill` (0,2,0) outranks `.pill-on` (0,1,0), so turning the toggle on turned the black "All" chip into an empty outline. A selected pill is already opaque and needs only the blur removed, not a new background. The toggle's own DOM test passed clean through this — the screenshot caught it.

**THE MOTION AUDIT IS CLOSED (2026-08-29) — two shipped, one deliberately not.** Scanned all five motion dimensions across styles.css. **Shipped: sheets now leave.** `sheetUp` existed for the open only and sheets are conditionally rendered, so every sheet in the app rose in over 450ms and then vanished in zero — and that got worse the moment Escape started closing eleven dialogs, because a keyboard close has no gesture to explain the jump. `src/lib/sheet-exit.js` holds the close 260ms (asymmetric on purpose: an opening sheet is an invitation, a closing one should get out of the way), then calls the real onClose. CSS alone cannot do this — `@starting-style` with `allow-discrete` needs the node to stay in the DOM and React removes it. **The wiring trick is worth reusing: the hook SHADOWS the prop** (`onClose: rawClose` in the signature, `const { closing, onClose } = useSheetExit(rawClose)` at the top), so every existing onClose call inside the component — scrim taps, close buttons, Escape, post-submit — routes through the animated close with no call-site changes. **Shipped: 25 distinct durations tokenised to 5** (`--t-tap/-press/-state/-panel/-glide`), grouped by what the motion does rather than by nearest number.

**DO NOT RE-FLAG THE NAV PILL (2026-08-29). It was measured and it is fine.** It animates five layout properties — margin, padding, min-height, max-height, width/height — across four selectors on every scroll, which reads as an obvious performance bug and is not one. `.tabbar` is `position: fixed`, so the relayout is scoped to its own subtree (a few nav items, not the document), and `backdrop-filter: blur(10px)` on it costs nothing measurable either. Measured at 4x CPU throttle over six runs: **median frame 16.7ms, worst frame ever seen 17.6ms, ZERO dropped frames** — a locked 60fps. A trace across eight shrink/grow cycles produced **no ForcedReflow insight at all**. The only artifact is CLS 0.0069, ~7% of the "good" budget, and probably not even real: those scrolls were driven programmatically, and shifts within 500ms of genuine user input are excluded from CLS. Converting it to transform-based motion would change how the labels behave (they collapse today; a scale would shrink the text) to fix nothing. **The general lesson: property names are not costs. Animating layout properties inside a `position: fixed` subtree is cheap, and reading CSS said "problem" while the trace said "no" — the trace wins.** Contrast the map label pass, where reading and the trace agreed and the fix was worth 475ms -> 35ms.

**TOKENISING DURATIONS MUST NOT TOUCH `animation:` — the second time value is a DELAY.** `fadeUp 0.8s 0.2s ...` on .bottom-ui, and 0.25/0.3/0.35s on .dock/.scrubber/.metro-btn, is a **staggered entrance**. A blanket find-replace reads those as durations and flattens the choreography into a single beat, silently. The tokenising pass rewrites only the FIRST time value of each `transition:` segment and skips `animation:` entirely. Three durations are also left hardcoded on purpose because their usage matches no token: 0.9s (dying rows), 0.6s (crowd-fill bar), 0.45s (haunts map).

**VERIFY A MECHANICAL CSS EDIT BY DIFFING COMPUTED STYLES, NOT BY READING THE SUBSTITUTION.** 61 values were rewritten; capturing `transitionDuration` for every element in the document under the old stylesheet and again under the new one proved 50 of 65 animated elements byte-identical, 15 moved 10-20ms, largest shift 20ms against a 16.7ms frame, nothing dropped to 0s. It also explained an apparent discrepancy that would otherwise have been waved through: `.pill` computes 0.16/0.2/0.2 rather than its own rule's 0.2/0.25/0.25 because the element is `BUTTON.pill.filter-pill` and the later `.filter-pill` rule wins — pre-existing cascade, not the edit.

**`npm run deploy` NOW SHIPS THE APP TOO (2026-08-29) — the deploy contract changed.** The chain is `build -> push:pages -> ios -> build`, and BOTH oddities in that ordering are load-bearing. **Web ships before the iOS sync** so a Capacitor failure can never block a deploy of the live site. **The trailing second `build` is not redundant:** `npm run ios` runs `build:native`, which rebuilds dist at `--base=/`, so without it every deploy would leave dist in NATIVE shape — and the documented way to verify a deploy here is comparing dist's hashed bundle against the CDN, which would then never match and spin forever. Do not "clean up" either one. The gh-pages push is now its own `push:pages` script.

**THE iOS APP HAD SILENTLY DRIFTED 38 COMMITS BEHIND (2026-08-29).** One codebase — Capacitor's `webDir` is `dist`, so the app is a shell around the same React build — but the native payload was a separate manual step nobody ran, last built 2026-08-28 12:36 while the site moved on. That is what the deploy change above fixes. **Verify the payload by CONTENT, never by bundle hash:** web builds at `base: /hum/` and native at `/`, so the hashes are supposed to differ and comparing them proves nothing (grep the payload for a string you just shipped instead). `ios/App/App/public` is gitignored, so a sync never shows up in `git status`. **Deploy still does not put anything on the handset** — that needs Xcode and the device, recipe in `ios/DEVICE-INSTALL.md`.

**ESCAPE NOW CLOSES SHEETS — 10 OF 11 NEVER DID (2026-08-29).** Found by sweeping for the class of bug behind the hero fix. The hero was unique: every other bare `onClick` is a modal scrim, where click-to-dismiss is a redundant convenience and the backdrop correctly is not a tab stop. But the assumption UNDER those scrims was wrong — a non-focusable scrim is only acceptable if Escape closes the dialog, and every sheet carries `role="dialog"` while only SearchSheet handled the key (on its input, so it worked only while that input had focus). `src/lib/escape.js` keeps a **LIFO stack of refs** — refs rather than the callbacks because `onClose` is nearly always an inline arrow that would re-order the stack on every parent render; `null` keeps a closed panel registered but inert so Escape falls through. **Sheets stack, so test the stack** — the single-sheet case passes with a naive per-sheet window listener too, and only stacking tells a correct implementation from one that closes everything at once.

**THE MAP'S LABEL COLLISION PASS WAS THE WHOLE PERFORMANCE STORY (2026-08-29).** Found with a Chrome DevTools trace at 4x CPU / Fast 4G — the first time hum's load was ever measured. Headline numbers are fine and were already fine: **LCP 1146ms, CLS 0.00**, Lighthouse a11y 96 / best-practices 100 / SEO 100. The cost was elsewhere: **475ms of forced reflow**, all of it in `apply()` in CityMap, which interleaved class writes with `getBoundingClientRect()` reads — ~216 synchronous layouts on EVERY moveend and zoomend, to place 13 visible names. Now reads-then-computes-then-writes; the flip to the other side of a dot is arithmetic (`top: 100%+5` vs `bottom: 100%+5`, same label height), so it needs no DOM write. **One pass 41.9ms -> 9.4ms; total reflow 475ms -> 35ms.** The refactor was proven behaviour-preserving by running both builds in the same minute and diffing the outcome — identical nolabel (78), identical flipped-up (18), same 13 names — which is the only way to safely rewrite something this visible. Method is reusable and cheap: `mcp__plugin_chrome-devtools-mcp_*` (performance_start_trace, lighthouse_audit, evaluate_script).

**MAP NAMES SIT ON FOUR SIDES OF A BUBBLE NOW (2026-08-29).** The cause of the density problem was the candidate set, not the algorithm: a name could only go directly below or above its bubble, and at this density the column over and under a bubble is nearly always spoken for while the space BESIDE it usually is not. Four positions — down, up, right, left — took names in the opening viewport from 13 to 17, with 31 placed to a side. Cheap only because the earlier reflow work made placement pure arithmetic; one pass is 1.6ms. The position a label already holds is tried first so names do not hop around on every pan, and names slide along the viewport edge (handed to CSS as --lx/--ly so the geometry tested is the geometry that renders). **A name that still overhangs after sliding is KEPT, not dropped** — rejecting them cost six names, and the basemap clips its own labels at the edge anyway, so a half-read name at the margin is ordinary map behaviour rather than a defect.

**DENSITY IS BEATING THE LABEL SYSTEM.** Measured, not eyeballed: of 84 markers in the opening viewport, **78 end up with no name at all** — the map is mostly a field of anonymous photo bubbles you must tap to identify. The rationing logic is working exactly as written; there is simply far more demand than supply. Avi has not ruled on this yet. It is the one genuinely open design question on the map, and it gets worse with every venue added.

**THE TONIGHT HERO WAS NOT REACHABLE BY KEYBOARD (2026-08-29).** `onClick` sat on a non-interactive `<article>`, so the global focus ring at styles.css:67 had nothing to attach to — a keyboard or switch user could tab to the `@handle` INSIDE the card but never the card itself. Fixed with a stretched `<button class="tp-hero-hit">` rather than `role="button"` on the article, because the post hero nests a real button and a button role must not wrap focusable descendants. The text layer is `pointer-events: none` and the handle re-enables itself above it — hit-test that layering, it is the part that breaks silently. Lighthouse a11y was 96 before this, so a green score did not surface it.
